# Opportunity Solution Trees

**Author:** Teresa Torres  
**Source:** "Continuous Discovery Habits" + industry leaders #67

---

## Problem

Skaczemy od problemu do rozwiązania bez eksploracji alternatyw.

## What Is It

Wizualna mapa od business outcome → opportunities → solutions → experiments.

---

## Structure

```
                    [Business Outcome]
                           |
        ┌──────────────────┼──────────────────┐
        |                  |                  |
   [Opportunity 1]   [Opportunity 2]   [Opportunity 3]
        |                  |                  |
    ┌───┼───┐          ┌───┼───┐          ┌───┼───┐
    |   |   |          |   |   |          |   |   |
   [S1][S2][S3]       [S1][S2][S3]       [S1][S2][S3]
    |   |   |          |   |   |          |   |   |
   [E] [E] [E]        [E] [E] [E]        [E] [E] [E]

S = Solution idea
E = Experiment
```

---

## How to Build

### Step 1: Define Business Outcome

- Nie feature ("ship dashboard")
- Outcome ("increase activation rate from 40% to 60%")
- Measurable, time-bound

### Step 2: Discover Opportunities (customer pain points)

- Continuous interviews (min. 1 per week)
- "What's frustrating about [current process]?"
- Grupuj w tematy

### Step 3: Generate Solutions

- Dla każdej opportunity, wymyśl 3+ rozwiązania
- Nie oceniaj jeszcze - diverge first

### Step 4: Design Experiments

- Dla każdego solution: "Jak możemy to przetestować w 1 tydzień?"
- Prototype, fake door test, concierge MVP

---

## Example

```
Outcome: Increase trial-to-paid conversion from 15% to 25%

Opportunity 1: Users don't understand value in trial
├─ Solution 1: Interactive onboarding tour
│  └─ Experiment: Loom video walkthrough (1 week)
├─ Solution 2: Success milestones
│  └─ Experiment: Email sequence with "wins" (1 week)
└─ Solution 3: Personalized demo
   └─ Experiment: Calendly link in trial email (1 week)

Opportunity 2: Trial is too short (7 days)
├─ Solution 1: Extend to 14 days
├─ Solution 2: Pause trial feature
└─ Solution 3: "Time left" reminders
```

---

## Quality Checks

- [ ] Outcome is measurable (not "improve UX")
- [ ] Opportunities come from customer research (not assumptions)
- [ ] Multiple solutions per opportunity (not jumping to first idea)
- [ ] Experiments are < 2 weeks (not "build full feature")
